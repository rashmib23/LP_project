1. LEARNING OBJECTIVES
------------------------------------------------------------
By the end of this lesson, students will be able to:
  a) Differentiate between Distance Vector and Link State routing paradigms.
  b) Analyze the step-by-step execution of Dijkstra's algorithm on a given network graph.
  c) Examine the Bellman-Ford algorithm and trace it through a sample topology.
  d) Compare the two algorithms with respect to time complexity, memory usage,
     convergence speed, and loop-prevention.
  e) Investigate failure scenarios (node failure, link cost change) and categorize
     their impact on each algorithm's behavior.
  f) Distinguish between count-to-infinity and split-horizon solutions in
     Distance Vector routing.

Bloom's Level : Analyze (a–f) with elements of Understand and Evaluate

3. CONTENT OUTLINE
------------------------------------------------------------

3.1 Routing Overview (10 min)
    • Goal of routing: find least-cost path from source to all destinations.
    • Routing table: maintained by each router; maps destination to next hop.
    • Classification: static vs. dynamic; intra-domain vs. inter-domain.
    • Two classes of dynamic algorithms: Link State (LS) and Distance Vector (DV).

3.2 Dijkstra's Algorithm – Link State Routing (25 min)
    • Each node has complete topology knowledge (via flooding of LSAs).
    • Algorithm: iterative; at each step selects unvisited node with minimum
      known distance; relaxes neighbour edges.
    • Complexity: O(n²) basic; O((n + e) log n) with min-heap.
    • Trace example: 6-node graph; students follow step-by-step on handout.
    • Disadvantage: oscillation if link costs depend on traffic load.

3.3 Bellman-Ford Algorithm – Distance Vector Routing (20 min)
    • Each node knows only its direct neighbours' costs; shares distance
      vector with neighbours; iterates until convergence.
    • Update rule: d(x,y) = min over v { c(x,v) + d(v,y) }
    • Convergence: O(n) rounds; O(n·e) total work.
    • Problem: count-to-infinity on link failure.
    • Fixes: split-horizon, poison reverse.

3.4 Comparative Discussion (25 min)
    The class is divided into two groups:
    Group A argues the case for Dijkstra / OSPF (real-world LS protocol).
    Group B argues the case for Bellman-Ford / RIP (real-world DV protocol).

    Discussion prompts:
    1. Which algorithm converges faster after a topology change? Why?
    2. Which consumes more memory per router? Justify with the data structures involved.
    3. For an ISP with 500 routers, which would you deploy and why?
    4. How does each algorithm detect and handle a failed link?

    Groups discuss for 10 minutes, then present findings (5 min each).
    Instructor moderates and corrects misconceptions.

3.5 Wrap-up and Inquiry (10 min)
    • Instructor poses: "BGP, used between ISPs, is a Path Vector protocol.
      How does it differ from both DV and LS? What problem does it solve?"
    • Students investigate in pairs using textbook / notes (5 min), then
      share hypotheses — to be formally answered in next class.

------------------------------------------------------------
4. TEACHING METHODS AND STRATEGIES
------------------------------------------------------------

  Method 1 – Lecture and Whiteboard (30 min)
    Structured lecture with worked examples on the whiteboard. The 6-node
    graph is drawn and Dijkstra's table built iteratively with student input.
    Bellman-Ford update rounds are traced similarly.

  Method 2 – Discussion-Based / Debate (25 min)
    Structured group debate (A vs. B) with defined roles. Students must
    support arguments with algorithmic evidence from today's content.
    Think-pair-share before the group presentations.

  Method 3 – Inquiry-Based Reflection (10 min)
    Open-ended BGP question requires students to extend today's knowledge
    by researching and formulating a hypothesis — fosters independent inquiry.

  Method 4 – Demonstration (10 min)
    Instructor uses an online network simulator (Packet Tracer screenshots
    projected) to show OSPF and RIP convergence side by side after a link failure.

  Method 5 – Brainstorm (5 min)
    Students brainstorm real-world factors (network size, admin overhead,
    security) that influence which protocol an organisation would choose.
